How the key scan works

Click keys to press or release them. Watch the firmware drain one row at a time, and see which column wires drop to 0.

3.3 V, reads 1 0 V (drained), reads 0 row left alone (floating)

  1. At rest every column is at 3.3 V. The pull-up at the top of each column (the zigzag, a weak resistor) keeps "filling" the wire. The chip reads 1.
  2. The firmware drains one row by connecting it to 0 V. Only one, so it knows which row it is testing.
  3. A pressed key joins its row and its column. If its row is the drained one, the column empties through the key and reads 0. The thin pull-up can't keep it full.
  4. The chip reads all 8 columns at once. A 0 in column c while row r is drained means the key at that crossing is pressed.
  5. Next row, and repeat. On the real toy all 4 rows take a few milliseconds, and the whole pass repeats hundreds of times a second.

"Try 5 + 8 + 13" shows the problem we stopped at: when row AB1 is drained, the current sneaks backwards through key 5, so EF7 drops too and key 16 shows up even though nobody pressed it.
